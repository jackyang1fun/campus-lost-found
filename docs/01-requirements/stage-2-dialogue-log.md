## 第 1 轮：平台与范围基线

### 虚拟同伴

完成对 V1 初稿的读取，指出四项主要缺口：

1. 初稿假设 Web 前后端，与无障碍任务采用的 Windows 桌面平台冲突。
2. 校园卡认证、匿名聊天、智能匹配、定期备份和争议处理没有完整纳入。
3. 缺少屏幕阅读器、键盘、焦点和高对比度需求。
4. 非功能需求不可测试。

提出三个问题：

- 最终平台选择 Windows 桌面、Web，还是桌面优先。
- 开发人数、时间以及校园卡认证接口条件。
- 六项功能的“必须 / 可选 / 不做”取舍。

### 学生

- 选择 Windows 桌面应用。
- 暂不回答开发人数和开发时间。
- 校园卡认证不需要真实接口，模拟实现即可。
- 对六项功能依次给出：`1,2,2,2,1,2`，分别表示：
  - 校园卡绑定与认证：必须；
  - 身份唯一性校验：可选；
  - 匿名聊天：可选；
  - 智能信息匹配：可选；
  - 定期备份：必须；
  - 争议处理：可选。

## 第 2 轮：范围取舍与约束权衡

### 虚拟同伴

指出“校园卡认证必须但身份唯一可选”的矛盾，并说明原任务把匿名沟通、智能匹配和争议处理列为子系统能力。建议采用“基础能力必须、增强能力可选”的分层：

- 校园卡模拟认证与唯一卡号绑定必须；
- 匿名文字聊天必须；
- 分类、地点、时间接近度和关键词的规则匹配必须；
- 自动备份和恢复必须；
- 争议提交、管理员调查、结论反馈必须；
- 机器学习、复杂图片识别、评分等高级能力可选。

要求学生在以下方案中裁决：

- A：采纳建议；
- B：维持原选择并接受覆盖风险；
- C：部分采纳。

### 学生

选择 `A`。

### 结果

六项相关能力均保留，文字聊天、规则匹配和争议处理采用最小实现。该项建议为 `【VP-Adopted】`。

## 第 3 轮：角色、权限与认领流程

### 虚拟同伴

提出以下方案供裁决：

- 游客可浏览，但不能发布、认领或聊天；
- 校园卡号与账号一对一；
- 认领流程为发起认领、匿名沟通、发布者确认交接、更新结果；
- 普通用户看到匿名编号，管理员在争议处理时可查看真实账号和聊天；
- 高风险操作需要二次确认。

并提出三个问题：

1. 游客是否允许浏览和搜索。
2. 谁确认交接完成。
3. 匿名聊天的可见范围。

### 学生

回答：`1A、2A、3A`。

### 结果

- 游客允许浏览和搜索。
- 物品发布者确认交接完成。
- 双方匿名，管理员仅能为争议处理审计身份和聊天记录。

## 第 4 轮：非功能与无障碍验收

### 虚拟同伴

将初稿中的模糊描述转化为可验证标准，建议：

- 10,000 条数据下搜索不超过 1 秒，应用启动不超过 5 秒。
- 连续运行 2 小时、执行 200 次核心操作不崩溃且不丢失已提交数据。
- 密码不可逆哈希保存，校园卡号唯一，联系方式默认不公开。
- 每天首次启动自动备份，保留最近 7 份，支持恢复。
- 支持 Windows 10/11 x64、1366×768 和 100% 至 200% 缩放。
- 所有交互控件具有可读名称、角色和状态。
- 全部核心功能支持键盘、合理焦点和 Narrator。
- 跟随 Windows 高对比度，文本对比度至少 4.5:1，焦点至少 3:1。

要求学生选择：

- A：全部接受；
- B：调整数字；
- C：拒绝并给替代标准。

### 学生

选择 `A`。

### 结果

上述非功能与无障碍要求进入需求基线。

## 第 5 轮：角色切换与涉众博弈

### 虚拟同伴切换角色

虚拟同伴由需求工程师切换为“工期紧张、担心运维负担的校园项目发起人”，提出四项削减要求：

1. 删除智能匹配，只保留搜索。
2. 取消匿名聊天，直接公开联系方式。
3. 取消自动备份，只保留手工导出。
4. 将无障碍适配放到最后，时间不足时不做。

要求学生逐项作出接受、部分接受或拒绝，并给出理由。

### 学生

1. 接受删除智能匹配。
2. 部分接受：公开真实信息会降低安全性，保留匿名；管理员可查看双方信息并介入协商。
3. 部分接受：最好仍提供自动备份。
4. 部分接受：能够完成就实施；工期不足时可以酌情削减。

### 虚拟同伴复核

- 指出完全删除智能匹配与原题不一致，建议采用基础关联匹配。
- 采纳“普通用户匿名、管理员可审计并协商”。
- 自动备份是原题系统管理能力和已接受的非功能要求，不能降为“有空再做”。
- 无障碍是本次专项任务的硬要求，不能整体削减；工期压力应先影响评分、推荐等扩展能力。
- 自主增加“需求—风险—验收方式”矩阵分析任务。

## 第 6 轮：最终范围裁决

### 虚拟同伴

提出：

- A：保留最多 10 条基于分类、地点、关键词和时间接近度的基础关联候选；
- B：完全删除匹配；
- C：匹配延后。

### 学生

选择 `A`。

### 结果

智能匹配修订为可解释的规则匹配：

- 候选显示匹配依据；
- 最多显示 10 条；
- 不自动完成认领；
- 不使用机器学习。

## 第 7 轮：单机与分发边界

### 虚拟同伴

说明单机与多机的差异，要求裁决：

- A：单机离线演示；
- B：局域网多人；
- C：每台电脑独立但数据不共享。

### 学生

选择 `A`，说明这是课程作业，不需要上线，只需要个人演示。随后询问最终版本能否在不同电脑单独运行。

### 虚拟同伴

确认采用 Windows x64 自包含发布后，复制到不同 Windows 10/11 电脑即可独立运行，无需安装 .NET 或联网；每台电脑的数据互相独立。跨设备通信和真实校园卡接口列为首期非目标。

- `【VP-Adopted】`：基础关联匹配、管理员匿名审计、每日自动备份、七份保留策略、角色权限、量化 NFR、无障碍验收、自包含发布。
