# CR-01 需求变更评估与实施记录

## 1. 变更请求

**变更名称：** 新增认领说明。

**提出角色：** AI 产品经理。

**最终裁决：** 项目负责人接受 CR-01。

**基线提交：** `c6587cc`

**CR-01 实现提交：** `6779e25`

**变更描述：**

用户发起认领时，必须填写 10 至 200 个字符的认领说明，例如物品隐蔽特征、遗失经过或其他能够证明归属的信息。该说明只对认领双方和管理员可见，信息发布者在认领管理和聊天页中均可查看。

## 2. 必要性与目标

系统原有的认领流程可以创建匿名会话，但不能在沟通前向发布者提供任何归属线索。该变更直接针对线上冒领问题：

- 增加第一层人工核验信息；
- 不要求上传敏感证件；
- 不公开真实姓名和联系方式；
- 发布者可在开始聊天前判断说明是否合理；
- 管理员仍可在争议处理中查看完整上下文。

## 3. 影响分析

| 影响对象 | 影响 | 处理方式 |
|---|---|---|
| 需求 FR-CLAIM-001 | 发起认领增加必填说明 | 修订验收标准 |
| 新增 FR-CLAIM-008 | 认领说明的隐私和可见范围 | 新增需求 |
| SQLite 数据库 | Claims 需要新字段 | 增加 schema v6 迁移 |
| ClaimService | 发起认领方法增加说明参数和长度校验 | 修改服务及调用方 |
| ClaimConversation | 向参与者返回认领说明 | 修改查询和展示模型 |
| 失物广场 | 发起认领前显示说明表单 | 页面内展开，不新开窗口 |
| 认领管理 | 展示双方可见的认领说明 | 增加说明区块 |
| 匿名聊天 | 会话顶部显示说明，供核对 | 增加说明文本 |
| 演示数据 | 增加账号和失物测试样本 | 更新种子工具 |
| RTM | 增加新需求并标记变更 | 由 v1.0 更新到 v1.1 |

未受影响的部分：校园卡认证、信息审核、基础匹配、备份结构、用户角色和自包含发布方式。

## 4. 最小化修改方案与顺序

1. 更新需求基线，增加 FR-CLAIM-008 并修订 FR-CLAIM-001。
2. 增加 schema v6 迁移，允许历史认领的说明字段为空。
3. 修改 `ClaimService.StartClaim`，校验 10 至 200 个字符。
4. 将说明加入认领查询和会话模型。
5. 在失物广场内增加说明输入区域。
6. 在认领管理和聊天页展示说明。
7. 更新自动化测试与 RTM。
8. 扩充演示账号和已审核失物数据。
9. 重新构建、回归测试并发布。

## 5. 风险与控制

| 风险 | 控制 |
|---|---|
| 说明可能包含隐私信息 | 仅认领双方和管理员可读取 |
| 说明可能被伪造 | 明确它只是核验线索，不代表系统完成真实性认定 |
| 历史数据缺少字段值 | 迁移字段允许 NULL，界面显示“历史记录未填写” |
| 必填字段影响原有测试 | 统一更新测试构造，并增加长度校验测试 |
| 长文本破坏布局 | 限制 200 字符，页面使用自动换行和滚动区域 |

## 6. 回归测试策略

### 必测范围

- 发起认领：空说明、过短说明、合法说明。
- 权限：发布者和认领人均可看到说明，非参与者不能进入会话。
- 认领流程：发起、聊天、取消、完成、关闭其他认领。
- 数据迁移：旧认领无说明时正常读取。
- 回归：匹配、审核、备份、争议和用户管理不受影响。
- 界面：说明表单和展示不产生新窗口，键盘可操作。

### 结果

实施后自动化测试、页面路由和发布包验证结果见 `docs/03-implementation/acceptance-test-report.md`。

## 7. 个人反思

CR-01 的价值不在于增加一个文本框，而在于把“认领资格说明”放在匿名沟通之前，使发布者在低信息暴露的前提下获得判断依据。变更被限制在 Claims 表、ClaimService、认领相关页面和 RTM 中，没有重写发布、匹配或审核逻辑，体现了通过最小修改而非整体重构来消化需求变化。
